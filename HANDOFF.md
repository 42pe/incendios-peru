# Handoff — Monitor de Incendios Forestales (Perú)

_Last updated: 2026-10-21. Written for the next agent/dev taking over._

## What this is

A **static, no-backend web app** that shows **active forest-fire hotspots
("focos de calor") in Peru on a map**. It was built as an **independent
stopgap** because Peru's official fire-monitoring platform —
**SERFOR's SAMI module** at `sniffs.serfor.gob.pe/monitoreo/incendiosforestales/`
— has been returning HTTP 403 (deliberately blocked at the proxy) **since
14 Oct 2026**, during an active and deadly fire season (12+ deaths, 950+
hotspots/24h reported by SENAMHI around 19 Oct).

It is **not an official source** and says so prominently. A foco de calor is a
satellite heat detection, not a confirmed fire.

## Why it works the way it does (key decisions)

- **SERFOR is only a *consumer* of satellite data**, not a producer. The real
  upstream is NASA/NOAA thermal-anomaly detections (VIIRS, MODIS, NOAA, GOES).
  So we bypass SERFOR entirely and pull the same upstream data ourselves.
- **Data source: INPE Queimadas** daily South-America CSV. Public, **no API key**,
  sends `Access-Control-Allow-Origin: *`, fresh (~hourly). We filter to Peru.
- **Scale/cost goal: "loaded a lot, costs nothing."** Achieved by making
  everything static: visitors only ever download small files from a CDN; they
  never hit INPE. The only moving part is a free GitHub Actions cron that
  rebuilds the data file every 30 min.
- **Basemap is self-hosted, not a tile service.** Because coverage is fixed
  (Peru only), we extracted a **Peru-only Protomaps/OSM vector basemap into one
  22 MB `.pmtiles` file** (zoom 0–10) and serve it as a static asset. No tile
  API key, no third-party rate limit — it scales with the CDN like everything
  else. Map engine is **MapLibre GL** reading the pmtiles via the `pmtiles`
  protocol, with an inline Protomaps style (Spanish labels).

## Architecture

```
INPE Queimadas CSV ──(every 30 min, GitHub Actions)──► scripts/build_data.py
                                                              │ filters Peru
                                                              ▼
                                               public/data/peru.geojson  (~350 KB)
                                               public/data/summary.json
public/data/basemap-peru.pmtiles (22 MB, static, generated once)
public/index.html  ── MapLibre GL + pmtiles, loads the two data files
                                                              │
                        many visitors ◄──── Cloudflare CDN ◄──┘  ($0, static)
```

## Repo layout

| Path | Role |
|---|---|
| `public/index.html` | The whole app (MapLibre GL, inline style, sidebar, "¿Cómo funciona?" modal). |
| `public/data/peru.geojson` | Hotspots, regenerated by the cron. **Do not hand-edit.** |
| `public/data/summary.json` | Totals, by-region counts without GOES (matches the default view) and GOES confirmed/total (debug/inspection). |
| `public/data/basemap-peru.pmtiles` | Bundled Peru vector basemap. Static; regenerate only to refresh OSM. |
| `scripts/build_data.py` | Fetches INPE (last N days), filters Peru, writes `public/data/`. |
| `.github/workflows/refresh-data.yml` | Cron (`*/30`) + manual dispatch; runs the script, commits if changed. |
| `wrangler.jsonc` | Cloudflare config: static-assets Worker serving `./public`. |
| `.claude/launch.json` | Local preview config (note gotcha below). |

## Run locally

```bash
python3 scripts/build_data.py 3     # refresh public/data/ (last 3 days)
```

**Gotcha:** `python3 -m http.server` does **not** support HTTP Range requests,
and pmtiles needs byte-serving, so the basemap won't load under it. Use the
range-capable helper (or `npx wrangler dev`):

```bash
python3 /private/tmp/.../scratchpad/rangeserver.py public 8790   # see note below
# then open http://localhost:8790
```
The `rangeserver.py` helper lives in this session's scratchpad (temporary). It's
~40 lines — re-create a range-capable static server if it's gone, or just use
`npx wrangler dev` which serves `public/` exactly as Cloudflare will.

## On every launch: refresh `public/data/news.json`

The "Noticias por región" modal reads `public/data/news.json`, which is
**curated by hand, not by the cron**. Refresh it on every deploy:

1. List regions with detections in `public/data/peru.geojson` (exclude `GOES*`).
2. Search news (last ~7 days) + COEN-INDECI reports per region, focusing on the
   provinces (`mun`) where detections cluster.
3. Per region set `status` — `coincide` | `parcial` | `anterior` |
   `sin_reportes` — plus a one-sentence Spanish `note` and `links`
   (`title`, `source`, `date`, `url`; https only). Methodology: README §8.
4. Update `checked` (UTC ISO) and `period`. The modal warns once it's >2 days old.

Keys in `regions` must match INPE's region names exactly (e.g. `Ancash`, no
accent). Regions with live detections but no entry show as "Aún sin revisar".

## Gotchas for the next agent

- **The bot pushes to `main` every 30 min** (data refresh). Always
  `git pull --rebase` before pushing. The bot only touches `public/data/`, so
  rebases are conflict-free against code changes.
- **CDN script integrity:** maplibre-gl 4.7.1 (cdnjs) and pmtiles 3.0.6
  (jsdelivr) use real SRI hashes — recompute if you bump versions, or the
  browser blocks them.
- **pmtiles file size:** keep the basemap under **25 MB** (Cloudflare static-
  asset per-file limit). Current extract is 22 MB at zoom 0–10. Raising maxzoom
  will exceed it — use Cloudflare R2 if you need deeper zoom.
- **Hotspot counts differ from SENAMHI/SERFOR** by design (different satellites,
  thresholds, and "reference satellite"). Don't treat a mismatch as a bug.
